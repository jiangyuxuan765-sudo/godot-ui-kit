## 一、控件清单与状态映射

两套 theme 覆盖相同控件。每个控件的**状态键名固定**，新主题必须一一对应填满。

### 基础控件

| 控件 | 状态键（styles/…） | 说明 |
|---|---|---|
| `Button` | normal / hover / pressed / disabled / focus | 主实心按钮 |
| `CheckBox` | normal / hover / pressed / disabled / focus | 复用按钮皮肤 |
| `CheckButton` | normal / hover / pressed / disabled / focus | 复用按钮皮肤 |
| `OptionButton` | normal / hover / pressed / disabled / focus | 下拉按钮 |
| `MenuButton` | normal / hover / pressed / disabled | 菜单按钮 |
| `LineEdit` | normal / focus / read_only | 单行输入框 |
| `TextEdit` | normal / focus | 多行输入框 |
| `ProgressBar` | background / fill | 进度条（底槽 + 填充） |
| `Panel` | panel | 弹窗框 |
| `PanelContainer` | panel | 容器（物品栏） |
| `PopupPanel` | panel | 弹出面板 |
| `HSeparator` | separator | 分界线 |
| `Label` | —（仅 font_size） | 文本 |

### 变体（Theme Type Variation）

变体 = 基于某基础控件、换一套皮肤的“子类型”。使用时在节点检查器 `Theme Type Variation` 填变体名。

| 变体名 | base_type | 用途 |
|---|---|---|
| `IconButton` | Button | 图标按钮（带按钮底） |
| `ButtonGrey` | Button | 灰色按钮 |
| `ButtonGreen` | Button | 绿色按钮 |
| `ButtonGold` | Button | 金色按钮（皇室战争套的"购买/领取"强调色） |
| `ButtonRed` | Button | 红色按钮（危险/放弃操作） |
| `ButtonWhite` | Button | 白色按钮（字体黑色） |
| `ButtonOutline` | Button | 白色描边按钮 |
| `PanelContainerScene` | PanelContainer | 场景栏 |
| `PanelContainerAchievement` | PanelContainer | 成就栏 |
| `PanelSuccess` | Panel | 成功提示 |
| `PanelFail` | Panel | 失败提示 |
| `PanelError` | Panel | 错误提示 |

`Icons` 类型下登记的命名图标，代码用 `get_theme_icon("名字", "Icons")` 取用（非控件皮肤，不会自动显示）：
`share / list / achievement / favorite / like / back / cancel / loading_ring / stepper / stepper2 / placeholder`

## 二、纯色 theme（第一套）规范

外观由 `StyleBoxFlat` 代码绘制。**风格 = 下列几组 token 的数值**，改数值即换风格。

### 设计 token

| token | 第一套取值 | 作用 |
|---|---|---|
| 主色（强调） | `Color(0.36, 0.70, 0.98)` 亮蓝 | Button normal/hover 底色 |
| 主色-按下 | `Color(0.18, 0.53, 0.82)` 深蓝 | pressed 底色（主色压暗） |
| 边框色 | `Color(0, 0.11, 0.21)` 深蓝黑 | 边框，宽度 2px |
| 中性底 | `黑 0.4 透明` | 输入框/次要控件背景 |
| 高亮/填充 | `白 1` | 滑块、进度填充、hover 高亮 |
| 圆角-主 | `12` | 主控件统一圆角 |
| 圆角-小 | `8` | 输入框、滑块局部 |
| 圆角-弹窗 | `24` | Panel |
| 阴影 | offset `(4,4)`, size 1；弹窗 size 8 | 投影 |
| 字号 | `36` | Button / Label |

### 出新纯色 theme 的方法

告诉 Claude 配色方向即可，例如：
> 参照规范和第一套，做一套暗黑霓虹风：主色霓虹紫 `Color(0.6,0.2,0.9)`，边框亮青，圆角保持 12，阴影加强

Claude 复制第一套结构，仅替换上述 token，输出 `第N套.tres`。

## 三、PNG theme（第二套）规范

外观由 `StyleBoxTexture` 引用图片。**风格 = 一套 PNG**。

### 9-patch 拉伸边距（texture_margin）规则

贴图靠 `texture_margin_*` 保护圆角/边框在拉伸时不变形。经验值（按贴图圆角大小定，约等于圆角像素半径）：

| 贴图类型 | texture_margin | 备注 |
|---|---|---|
| 实心按钮（圆角中） | 32 | 208×72 |
| 选中态（带外发光） | 54 + expand_margin 22 | 发光溢出用 expand |
| 图标按钮 | 30 | |
| 弹窗框/多行输入框 | 48 | 大圆角 |
| 单行输入框 | 40 | |
| 容器（物品/场景/成就栏） | 60 | |
| 进度条 | 16 | |
| 分界线 | 左右 6，无上下 | 细长条 |
| 白色/描边按钮 | 24 | 小圆角 122×54 |

其他要点：
- 输入框加 `content_margin`（文字不贴边）：单行左右 24；多行左右 24 上下 16
- 进度条 background 与 fill **不能用同一张图**，否则两层叠加会重叠穿帮。做法见 5.7
- 图标按钮**不要**同时给节点设 `icon` 为同一张按钮图，会“按钮里套按钮”

### PNG 命名约定（重要）

新素材沿用现有命名，Claude 才能自动对应控件。放到独立文件夹如 `UI/新风格名/`：

```
实心按钮正常状态大 / 实心按钮选中状态大 / 实心按钮按压状态大 / 实心按钮禁用状态大
图标按钮正常状态大 / 图标按钮选中状态大 / 图标按钮按压状态大 / 图标按钮禁用状态大
灰色实心按钮正常状态 …（选中/按压/禁用）
绿色实心按钮正常状态 …
白色实心按钮 / 白色描边按钮
单行输入框 / 多行输入框
线性进度条 / 弹窗分界线
弹窗框 / 物品栏 / 场景栏 / 成就栏
成功提示组件 / 失败提示组件 / 错误提示 / 加载弹窗
分享图标48 / 列表图标48 / 成就图标48 / 收藏图标48 / 点赞图标48 / 返回图标48 / 取消
环形加载指示器 / 步进指示器 / 步进指示器2 / 占位符
```

### 出新 PNG theme 的方法

1. 新素材放入 `UI/新风格名/`，命名照上表
2. 告诉 Claude：
> 把 `UI/新风格名` 这套图，按规范和第二套的结构接入，生成 `第N套-图片.tres`

Claude 读取每张图的 uid + 尺寸，按映射整套生成并校验引用。

## 四、通用约定

- **每套 theme 独立文件**，不改动已有套，命名 `第N套.tres` / `第N套-图片.tres`
- **生成后校验**：无悬空 SubResource/ExtResource 引用
- **测试场景默认全量展示**：一套素材里**每张图都要在测试场景出现**（皮肤图看控件效果，内容图用 TextureRect/TextureButton 摆出），不要只挑代表性的几张。生成后做“着落自查”：遍历素材目录，确认每张 png 的 uid 都被 theme 或测试场景引用，无遗漏。（曾漏掉深蓝科技风的 tree/竖导航栏等 16 张，就是因为只放了代表性素材）
- **预览**：打开对应测试场景，按 F6
- **运行时换肤**：`control.theme = load("res://theme/第N套.tres")`
- **Godot 版本**：4.7；竖屏 750×1280

### 4.1 改名/移动图片目录的正确姿势（重要，踩过坑）

theme 靠 `path=` 和 `uid=` 引用图片。**在 Godot 编辑器外部改动会导致引用断裂**：

- ✅ **正确**：在 Godot「文件系统」面板里右键 → 重命名/移动。Godot 会自动更新所有引用该文件的 `.tres` / `.tscn`。
- ❌ **危险**：在访达（Finder）里改目录名或文件名。Godot 不知情，theme 里的旧路径全部失效 → 报“文件丢失”、测试场景跑不出来。

**已发生案例**：`UI/游戏UI/` 在外部被改名为 `UI/蓝色纯色第一套UI/`，导致第二套 theme 的 41 张图全部失效。

**若已经在外部改名，修复方法**：
1. 批量替换 theme 里的旧路径为新路径（`res://UI/旧名/` → `res://UI/新名/`）
2. 补回被删的 uid（Godot 重存 theme 时可能只留 path 删掉 uid，双保险要两者都对）：从新目录每个 `.png.import` 读 `uid://…`，写回对应 ext_resource 行
3. 校验：图片都存在 + uid 与实际一致 + 无头加载无报错（见 5.6）

### 4.2 替换图片内容（去水印/改版）的正确姿势

只想换图、不改名时：

- ✅ **只覆盖 `.png` 本身，保留同名 `.png.import`**。uid 不变，所有引用无需改动，Godot 自动重新导入新图。
- ❌ **连 `.png.import` 一起替换/删除**。会触发重新导入生成**全新 uid**，旧引用（theme + 场景）全部失效，需逐一更新 uid。

**已发生案例**：像素风替换去水印图时连 import 一起没了，33 张图 uid 全变，theme(8 处)+场景(21 处)引用都得重写。

## 五、非标准素材接入经验（像素风/第三套）

并非每套素材都像第二套那样“四态齐全、命名规整”。第三套（像素风生存式）总结出以下处理套路，接类似素材时照此办。

### 5.1 项目外素材：必须先拷进项目并导入

theme 只能引用**项目内、已导入（有 uid）**的图。若素材在 `/Users/mac/游戏UI素材库/...` 等项目外位置：

1. 拷进项目：`UI/新风格名/`（macOS 中文路径在 shell 里编码不稳，Claude 拷贝可能失败，**由用户手动拖入最稳**）
2. 生成 uid：命令行跑一次无头导入 —
   `/Applications/Godot.app/Contents/MacOS/Godot --headless --import`
   （或直接在 Godot 编辑器里打开项目，会自动导入）
3. 校验：`UI/新风格名/` 下每张 png 都应出现同名 `.png.import`，内含 `uid://…`

### 5.2 仅有正常态 → modulate 模拟四态

素材常常只给“正常状态”一张按钮图，没有 选中/按压/禁用。用 `StyleBoxTexture` 的 `modulate_color` 在同一张图上调明暗即可：

| 状态 | modulate_color | 效果 |
|---|---|---|
| normal | 不设 | 原色 |
| hover | `Color(1.15, 1.15, 1.15, 1)` | 微亮 |
| pressed | `Color(0.75, 0.75, 0.75, 1)` | 压暗 |
| disabled | `Color(0.5, 0.5, 0.5, 0.6)` | 变灰+半透明 |
| focus | 复用 hover | |

### 5.3 像素图 → Nearest 过滤（否则糊）

Godot 4 的纹理过滤是**节点级属性**，不在 import 文件里。在测试/使用场景的**根 Control** 上设 `texture_filter = 1`（Nearest），会向下继承给所有子节点，像素保持锐利。好处：只作用于该场景，不影响其它平滑贴图的 theme。

### 5.4 烤了内容的按钮 → 变体 或 TextureButton

有些“按钮”图已烤入图标/文字（如宝箱按钮、剑按钮、菜单按钮），**不能当通用空框皮肤**。两种用法：

- **做成 theme 变体**（整张当皮肤，四态用 modulate）：适合会被文字/布局复用的，如 `ButtonMenu`、`ButtonChest`。
- **场景里直接用 `TextureButton` 节点**（texture_normal 设为该图）：适合各自独立、尺寸不一的功能按钮（职业/提示按钮）。规范上这类属“内容图”，不强行塞进 theme。

**可复用脚本 `scenes/像素图标按钮.gd`**（uid `uid://m4wv5b6kjefw`）：给 TextureButton 挂上即可，单张贴图自动模拟交互——
- 悬停变亮 / 按下压暗 / 禁用变灰（`self_modulate`，明暗程度可在检查器 `@export` 调）
- 默认 `pressed` 信号打印 `[图标按钮] 点击: 节点名`，接自己逻辑时替换该连接即可
- 节点配置：`texture_normal` = 图，`ignore_texture_size = true`，`stretch_mode = 5`（保持比例），`custom_minimum_size` = 图原尺寸
- 用法示例见 `scenes/theme测试-像素.tscn` 的 PromptRow / ClassRow

### 5.5 判断“皮肤图” vs “内容图”

- **皮肤图**（空框、纯外观、可拉伸包裹文字）→ 进 theme 做 StyleBoxTexture
- **内容图**（烤了图案、图标、状态条快照）→ 场景里用 TextureRect / TextureButton 原尺寸摆放

接图前先**逐张看图**（Read 图片）确认属于哪类，再决定映射，避免把“内容图”误当皮肤导致拉伸变形。

### 5.6 用无头模式实测（强烈推荐）

生成后除了查悬空引用，还可真正加载场景验证：
```
/Applications/Godot.app/Contents/MacOS/Godot --headless --quit-after 5 "res://scenes/theme测试-像素.tscn" 2>&1 | grep -iE "error|invalid|failed"
```
无输出 = 无报错，比只查文本引用更可靠。

### 5.6b 着落自查：确认每张素材都被用到（配合“全量展示”约定）

生成完 theme + 测试场景后，跑一遍确认素材目录里**没有哪张图被漏掉**（未进 theme 也未在场景展示）：
```bash
DIR="UI/风格名"; THEME="theme/第N套.tres"; SCENE="scenes/theme测试-XX.tscn"
find "$DIR" -maxdepth 1 -iname "*.png" | while read f; do
  uid=$(grep -m1 "uid=" "$f.import" 2>/dev/null | perl -ne 'print $1 if m{(uid://[^"]+)"}')
  used=0
  grep -q "$uid" "$THEME" 2>/dev/null && used=1
  grep -q "$uid" "$SCENE" 2>/dev/null && used=1
  [ "$used" -eq 0 ] && echo "未用: $(basename "$f" .png)"
done; echo "--自查完（无“未用”=全覆盖）--"
```

### 5.7 进度条：一张“满格图” → 静态显示（默认，最省事）

素材常只给一张**烤好的满格进度条**（金属框+橙色填充连在一起，如金属第四套的 `横条形进度条.png`）。这类图**没有单独的空槽/填充层**，做动态进度会踩坑，逐条说明：

**默认方案：当静态满格图（推荐）**
```
[sub_resource type="StyleBoxTexture" id="Prog_bg"]
texture = ExtResource("满格图")
texture_margin_* = ...        ; 9-patch 保护圆角

[sub_resource type="StyleBoxEmpty" id="Prog_fill"]   ; fill 留空，不叠加
```
- `background` = 满格原图，`fill` = `StyleBoxEmpty`（空）
- 结果：进度条就显示原图一张，**无重叠、最忠于美术**
- 适合血条框、装饰条等**不需要真实增减**的场景
- 测试场景里把 ProgressBar 的 `value` 设 100、尺寸设满格图的整数倍即可

**踩过的坑（别再犯）**：
- ❌ background 和 fill 都用满格图 → 两层橙色叠加**重叠**穿帮
- ❌ 想“抠出橙色芯当 fill” → 满格图自带金属框，region 抠图靠像素目测反复调，且总会带到边框残影，不值当
- ❌ 给 background 压暗 modulate 假装空槽 → 改变了原图质感，“看着不像原图”

**若确实要动态进度**：必须有**单独的空槽图**（只有金属框+暗内槽、无填充）。则：
- `background` = 空槽图；`fill` = 纯色块（StyleBoxFlat，取原图填充色）
- 靠 `background` 的 `content_margin` 把 fill 框进暗槽内（值 = 暗槽内边界像素，放大图10倍量取）
- **关键约束**：content_margin 是固定像素、**不随控件缩放**。所以进度条显示尺寸必须是**空槽图原尺寸的整数倍**，且 content_margin 同倍放大，橙色才对得准。尺寸不固定就对不上。
- 案例：金属第四套曾用 `横条形进度条底槽.png`(145×32) 做过，暗槽内边界约左右13/上下10；后因需求改回静态满格图。

### 5.8 拆解部件 → 拼可交互控件（进度条/滑块/摇杆等）

当美术**把组件拆成独立 PNG**（空槽、填充、拖动键分开），就能做**真交互**控件。深蓝科技第六套踩通了这条路，记录关键点。

**进度条/滑块：用 `TextureProgressBar`，不要用 ProgressBar/HSlider**
- **为什么**：`ProgressBar`/`HSlider` 用 StyleBox 铺背景，控件高度一旦不等于图高，空槽就被**压扁/裁剪**。`TextureProgressBar` 按贴图**原始像素**画（`texture_under`=空槽、`texture_progress`=填充），不压扁。
- **配置**：
  ```
  [node ... type="TextureProgressBar"]
  custom_minimum_size = Vector2(空槽宽, 空槽高)   ; 严格按图原尺寸，别放大
  texture_under = 空槽图
  texture_progress = 填充图
  texture_progress_offset = Vector2(左留边, 上留边)  ; 填充嵌进内槽的偏移
  ```
- **留边算法**：填充比空槽小，`offset = ((空槽宽-填充宽)/2, (空槽高-填充高)/2)`。例：空槽301×32、填充273×17 → offset=(14, 7)。
- **纯展示进度条**（血条，代码控数值）：到此为止，不挂脚本。

**加拖动 → 挂 `贴图滑块.gd`（uid `uid://ddjvyvijkqxa2`）**
- 在 TextureProgressBar 下加一个**名为 `Grabber` 的子 TextureRect**（拖动键图），挂此脚本即可拖动。
- 脚本自动：Grabber 随 value 移动并竖直居中、鼠标拖动/点轨道改 value。
- `track_margin` 参数 = 轨道左右内边距，设成和 `texture_progress_offset.x` 一致。
- ⚠️ **两端装饰不对称 → 用 `track_margin_end` 单独设终点留边**（欧式奇幻踩过）：`track_margin` 默认**左右(上下)对称**。若为避让头部大装饰(如左宝石)把它设大，尾端(右/顶)也会被同样内缩、**填充和拖动键拖不到底**。→ 脚本另有 `track_margin_end`(默认 <0 = 沿用 track_margin 保持对称，不影响其他套)：`track_margin`=起点(左/底)留边、`track_margin_end`=终点(右/顶)留边，分开设即可两端各自贴合装饰。例：横滑块左宝石35+右小装饰14 → `track_margin=35, track_margin_end=14`；滚动条(拖动键74宽)左=宝石35+半键37=72、右=装饰14+半键37=51。竖版同理(起点=底、终点=顶)。

**滚动条 = 滑块去掉填充**：滚动条只有空槽+拖动键、**无填充层**（拖动键在槽里滑，不显示已滑过部分）。做法同上，但 TextureProgressBar **不设 `texture_progress`**，只设 `texture_under`（空槽）+ Grabber（拖动键）+ `贴图滑块.gd`。`track_margin` 设成拖动键半宽（如拖动键55宽→28），让拖动键中心不越出槽两端。深蓝科技第六套的滚动条(空槽301×17+拖动键55×9)即此法。注：这是「独立可拖的滚动条外观」；若要真正带动列表滚动，需接 ScrollContainer/HScrollBar，另一套接法。

**踩过的坑（血泪，务必记住）**：
- ❌ **别用 `@export var xxx: Node` + 场景里 `xxx = NodePath(...)`**：类型不匹配（节点引用 vs NodePath），赋值静默失败、引用为 null、脚本整个不工作且**不报错**。→ 正解：脚本内 `get_node_or_null("Grabber")` 自己找子节点，不靠 @export 传引用。
- ❌ 拖动键 TextureRect 默认 `mouse_filter=STOP` 会**吞掉点击**，滑块拖不动。→ 给拖动键设 `MOUSE_FILTER_IGNORE`（点击穿透），滑块本体设 `MOUSE_FILTER_STOP`。
- ❌ 在 `_ready` 立刻算 Grabber 位置会**错**（布局没完成、size 还不对）。→ `await get_tree().process_frame` 后再算。
- ⚠️ **填充与拖动键交叉轴没对齐**（很常见）：拖动键脚本让 Grabber **交叉轴居中**（横滑块竖直居中、竖滑块水平居中），但**填充默认从控件边缘画起、不居中**。当填充图比空槽/控件在交叉轴上窄（如空槽25高、填充19高），填充就偏一边，和居中的拖动键错开几像素。→ **用 `texture_progress_offset` 把填充在交叉轴上居中**：横滑块设 `Vector2(0, (控件高-填充高)/2)`（如 `(0,3)`）、竖滑块设 `Vector2((控件宽-填充宽)/2, 0)`（如 `(3,0)`）。（日系/未完成两套都栽过；另一种解法是把控件交叉轴尺寸改成=填充尺寸，但用 offset 更不动别处。）验证：打印控件中心 vs Grabber 中心 vs 填充中心，三者对齐即成。
- ⚠️ **交互只在运行时生效**：编辑器视图里拖不动是正常的，必须运行场景。**Mac 运行当前场景 = ⌘R**（不是 F6；F6 被系统占用，或按 fn+F6）。

**⚠️ 空槽两端有装饰（宝石/端头）→ 填充要横向内缩，别盖住装饰**（欧式奇幻第九套踩通）：
有些空槽图**左右端各画了装饰**（如左端一颗宝石、右端一个端头），中间才是均匀凹槽。填充从控件边缘画起会**盖住这些装饰**。先扫素材确认装饰范围（`Image.load_from_file` + 逐列 `get_pixel` 看颜色突变处），再按控件类型内缩：
- **主题 `ProgressBar`（填充走 StyleBox）**：填充 StyleBox 加 **`expand_margin_left/right` 负值**内缩（如左装饰35px→`expand_margin_left = -35`、右装饰14px→`expand_margin_right = -14`）。同理竖向露上下边框用 `expand_margin_top/bottom` 负值。**注意**：ProgressBar 填充**不看背景 StyleBox 的 `content_margin`**（改了没反应，别在背景上设），只有填充自己的 `expand_margin` 生效。填充左边固定、右边随 value 伸缩，故左侧内缩恒定露装饰、右侧内缩只在 value 接近满时才顶到右装饰内侧。若要「填充无论多长都不越过端头」的硬边界，得改用 TextureProgressBar。
- **`TextureProgressBar`（滑块/滚动条）**：❌ **别指望 `texture_progress_offset` 避让装饰**。offset 只平移填充贴图起点，**不改 value→宽度的伸缩范围**：填充仍按 `ratio × 控件全宽` 生长，于是会溢出、看着不居中、末端和拖动键接不上（欧式奇幻栽过一次）。→ 正解：**删掉内置 `texture_progress`，改挂一个名为 `Fill` 的 `NinePatchRect` 子节点**，由 `贴图滑块.gd`/`贴图滑块竖.gd` 脚本控制其宽/高，让填充**从 `track_margin` 起、末端正好接到拖动键中心**，天然对齐、天然避让装饰。
  - `Fill` 配置：横版 `custom_minimum_size = Vector2(0, 填充高)` + `patch_margin_left/right`；竖版 `Vector2(填充宽, 0)` + `patch_margin_top/bottom`。`mouse_filter = 2`(IGNORE)。节点顺序放在 Grabber **之前**(填充在拖动键下层)。
  - 脚本对 `Fill` 是**可选**的(`get_node_or_null("Fill")`)：没有 Fill 子节点就退化成原来的 texture_progress 行为，**不影响其他套**。
  - `track_margin` 设成装饰宽(横版左装饰宽，如 35)，填充起点和拖动键起点都用它，二者对齐。
  - 滚动条无填充层则只需给拖动键 `track_margin` 设成装饰宽+拖动键半宽，让拖动键中心不进装饰区。

**严格按素材尺寸**：拆解部件的尺寸往往是设计者精确配套的（填充比空槽小的留边就是内槽位置）。**控件尺寸直接用图原始像素，别自己放大**，否则比例错、还会触发压扁。

**竖版滑块/进度条：需竖版空槽/填充图，不能直接拿横图竖用**。实践教训：横空槽是横长条（301×32），若只把控件宽高对调（32×301），横图会被**拉伸变形**。正确做法：
- **要一套竖版空槽/填充图**（如 `竖条形进度条空槽` 32×301、`竖条形进度条填充` 17×301，是横版的宽高对调重画）。拖动键是圆的可复用横版。
- `TextureProgressBar` 设 `fill_mode = 3`（`FILL_BOTTOM_TO_TOP`，从下往上）或 2（从上往下）。
- 控件尺寸 = 竖空槽原始尺寸；`texture_progress_offset` 按竖填充在竖槽的留边算（如竖槽32宽/竖填充17宽 → x=7，满高则 y=0）。
- 拖动脚本用 y 轴：见 `贴图滑块竖.gd`（uid `uid://bs7o1y35em46x`），与横版 `贴图滑块.gd` 同源、改 y 轴、越往上值越大。

### 5.9 虚拟摇杆 → `虚拟摇杆.gd`（uid `uid://cfvgvjabnihji`）

背景 TextureRect + 一个**名为 `Knob` 的子 TextureRect**（摇杆键），背景挂此脚本。
- 鼠标在背景内拖动，Knob 跟随并**限制在半径内**，松手**回中**。
- 对外：`output`（Vector2，-1~1）、`moved(vector)` 信号，可接移动逻辑。
- `max_radius` 参数 = Knob 可移动最大半径，留 0 自动取背景 1/4 宽。
- 同样遵守 5.8 的坑：get_node 找 Knob（不用 @export NodePath）、Knob 设 IGNORE、await 一帧再定位。
- 尺寸严格按图：背景/Knob 都用原始像素，Knob 初始居中。

### 5.10 导航栏（单选）→ `导航栏单选.gd`（uid `uid://bqg8cxu880ans`）

背景 TextureRect + **名为 `Highlight` 的选中框子节点** + 若干**名为 `Item0`/`Item1`/… 的图标子节点**，背景挂此脚本。
- 点击某图标 → 选中框移到它后面、发 `selected(index)` 信号，**单选**（同时只一个选中）。
- **图标位置要手动摆**（脚本只移选中框、不排版）：背景宽 / 图标数 = 每格宽，图标放各格中心（`offset_left = 格宽*(i+0.5) - 图标宽/2`），竖直居中。
- 横竖通用：竖导航栏同理，图标沿纵向均分，选中框用竖版选中框图。
- Item 若用 Button 类会自动接 `pressed`；用 TextureRect 则脚本接 `gui_input`。
- 图标水平/竖直位置纯靠估算 offset，**必须运行后目测微调**（背景两端常有留白，均分不一定准）。

**（可选）选中态换图**：若素材给了每个图标的「选中状态」图（选中时图标本身变样，不只是选中框移动），脚本支持自动换图——**给每个 Item 节点设两个 meta**：
```
metadata/normal_tex   = ExtResource("普通态图")
metadata/selected_tex = ExtResource("选中态图")
```
- `select(index)` 里 `_apply_selected_tex()`：选中项换 `selected_tex`、其余换回 `normal_tex`。TextureRect 换 `texture`、TextureButton 换 `texture_normal`。
- **可选、不破坏复用**：只有设了这两个 meta 的 Item 才换图；没设的（如科技套导航栏）行为完全不变。所以同一个 `导航栏单选.gd` 横竖、多套主题共用，互不影响。
- 效果 = 选中框移动 + 图标变选中态，两者叠加（日系套即如此；科技套只有选中框）。
- **⚠️ 普通态/选中态图尺寸不一致 → 偏移+大小突变（卡通果冻栽过）**：卡通果冻的普通态图各不同（102×99、76×95…），选中态图全是 148×148（带高亮外框）。若 Item 不设 `expand_mode`/`stretch_mode`，TextureRect 按**纹理原尺寸**画 → ①普通态各图大小参差、位置乱；②换选中态时尺寸从 ~100 暴涨到 148、明显位移。**解法**：所有 Item 用**统一固定框**（取选中态尺寸如 148×148）、居中在每格（`800/5` 每格 160，框居中），并设 `expand_mode = 1`（IGNORE_SIZE）。这样框不随纹理变，换图时**框不动、位置稳定**。
- **`stretch_mode` 决定普通态显示大小**：框统一后——`stretch_mode = 5`(KEEP_ASPECT_CENTERED) 会把小的普通态图**放大填满**框 → 普通态显得比选中态大；要普通态保持**原生大小**（和选中态里的图标一样大、选中只多外框）用 `stretch_mode = 3`(KEEP_CENTERED，原尺寸居中不缩放)。卡通果冻即用 3。

### 5.11 弹窗 + 独立按钮：组合拼装

美术常把「提示弹窗」拆成两块：**弹窗底图**（如 `成功提示弹窗`，上半烤了图标、下半留白）+ **独立按钮图**（如 `成功提示弹窗按钮`，空框可放文字）。这类要**两用**：按钮既配进弹窗、又能单独用。

**做法：按钮做成 theme 变体，弹窗用容器组合**
1. 按钮图 → theme 里做 Button 变体（如 `ButtonOk`/`ButtonFail`，modulate 三态）。这样按钮可复用、能 hover、能放文字。
2. 弹窗展示 = 一个 `Control` 容器，内含：
   - `TextureRect`（弹窗底图，铺满容器 `anchors_preset=15`）
   - `Button`（用按钮变体，绝对定位在弹窗下半留白处）
   ```
   [node name="OkBox" type="Control"]      ; 容器 = 弹窗原尺寸
   [node name="OkImg" type="TextureRect" parent="OkBox"]   ; anchors_preset=15 铺满
   [node name="OkButton" type="Button" parent="OkBox"]
     anchors_preset=7 (底边居中); offset_top≈-110, offset_bottom≈-43  ; 距底留白
     theme_type_variation=&"ButtonOk"
   ```
3. **同一按钮变体再单独摆一份**（HBox 里放 Button 用同变体），满足「按钮也要单独展示」。

**要点**：
- 按钮在弹窗上的竖直位置（offset_top/bottom）靠**弹窗底图的留白高度**估算，**运行后目测微调**。
- 一套弹窗按钮，theme 里定义一次变体，弹窗内和单独展示都引用它，不重复。
- 判断依据同 5.5：弹窗底图烤了图标=内容图(TextureRect)；按钮空框=皮肤(变体)。二者组合。

### 5.12 CheckButton 开关：用 icon，不是 styles（易配错）

**踩过的坑**：CheckButton（开关滑块）的 **开/关状态由 `icons/checked` 和 `icons/unchecked` 控制**，不是 styles。一开始误把开关图配成 `styles/normal` 背景 StyleBox → 开关图后面叠了个方框、且点击不切换。

**正确配法**：
```
CheckButton/styles/normal   = StyleBoxEmpty   ; 背景全设空，否则叠方框
CheckButton/styles/hover    = StyleBoxEmpty
CheckButton/styles/pressed  = StyleBoxEmpty
CheckButton/styles/disabled = StyleBoxEmpty
CheckButton/styles/focus    = StyleBoxEmpty
CheckButton/icons/checked   = 开态图（如青钮在右）
CheckButton/icons/unchecked = 关态图（如青钮在左）
CheckButton/icons/checked_disabled   = 开态图
CheckButton/icons/unchecked_disabled = 关态图
```
- 素材需**开/关两张完整开关图**。只有一张时先都填它占位，视觉切不出差异但点击有逻辑；补齐关态图后替换 unchecked。
- 对比：CheckBox（勾选框）同理，也是 checked/unchecked icon 控制勾。而普通 Button/开关“外框”才用 styles。

### 5.13 缺小图标 → 自己用 SVG 生成（勾号/箭头等）

素材缺一个简单小图标（如勾选框里的勾号、小箭头、加减号）时，**不用等美术给，可自己写 SVG**：Godot 原生导入 SVG（纯文本，无需任何外部图像工具）。

**做法**：
1. 在素材目录写一个 `.svg` 文件（rect/path 画图形）。例：勾选框选中态 = navy 圆角方块 + 青色勾号
   ```svg
   <svg width="25" height="25" viewBox="0 0 25 25" xmlns="http://www.w3.org/2000/svg">
     <rect x="1" y="1" width="23" height="23" rx="5" fill="#1e4160" stroke="#3a6a94" stroke-width="1.5"/>
     <path d="M6 12.8 L10.5 17.3 L19 7.5" fill="none" stroke="#6fe0f0" stroke-width="2.6" stroke-linecap="round" stroke-linejoin="round"/>
   </svg>
   ```
2. `--headless --import` 生成 uid，像普通贴图一样用。
3. **配色匹配现有素材**：用 sips 把参考图缩到 1×1 取平均色（`sips -z 1 1 图.png`），拿到主色再放进 SVG。
4. **预览**：`qlmanage -t -s 200 -o 输出目录 图.svg` 渲染成 PNG 检查效果（macOS 自带，比开 Godot 快）。

**优点**：尺寸随意、清晰不糊、颜色/粗细/位置随时改（改文本即可）。**适用**：勾号、箭头、加减号、分隔线等几何小图标；不适用复杂插画（那还得美术出图）。

**可用工具备忘**（本机环境）：
- ✅ `sips`：缩放/取色/格式转换（无合成）。
- ✅ `qlmanage`：SVG/图片渲染预览。
- ❌ ImageMagick、Python(PIL) 不可用 → 需合成/绘制时走 SVG 路线。

**高频场景：勾选框选中态缺勾号 → 用 SVG 合成一张「方块+勾号」替换**。很多素材的 CheckBox 选中态只是个纯色方块、没有勾号，视觉上和未选态区分不明显。做法：
1. 用 Godot 脚本 `Image.get_pixel()` 读原勾选框的**方块填充色和边框色**（比 sips 更准，能读边框）。
2. 写 SVG：`rect`（同色同圆角复刻方块）+ `path`（画勾号）。勾号颜色选**和主题强调色一致**、且在方块底色上够对比。
3. 导入后把 `CheckBox/icons/checked` 指向这张 SVG（`unchecked` 保持原无勾方块）。
4. 若 `Tree/icons/checked` 复用同一张，Tree 的勾选项也会跟着显示勾号（顺带受益）。
- 三套实例的配色规律（方块底色 → 勾号色）：科技 navy `#1e4160` → 青 `#6fe0f0`；日系 navy `#2e3263` → 浅蓝 `#91bff9`；未完成 米白 `#faf5eb` → 蓝 `#3f6f9f`。即**深底配亮勾、浅底配深/彩勾**。

### 5.14 CheckBox 交互三连修复：文本防偏移 / 居中 / 专用方形图

配 CheckBox（勾选框）时踩到的三个问题，一次记全：

1. **按压时文本偏移（很怪）**：默认若 `styles/pressed` 的 `content_margin` 和 `normal` 不一致，按下时文本会跳一下。
   **修法**：`styles/` 的 **normal / hover / pressed / disabled / focus 五态全部指向同一个 StyleBox**（如共用 `Btn_normal`）。五态背景一致 → 不管怎么点按，文本纹丝不动。
   ```
   CheckBox/styles/normal   = SubResource("Btn_normal")
   CheckBox/styles/hover    = SubResource("Btn_normal")
   CheckBox/styles/pressed  = SubResource("Btn_normal")
   CheckBox/styles/disabled = SubResource("Btn_normal")
   CheckBox/styles/focus    = SubResource("Btn_normal")
   ```
2. **文本居中**：CheckBox 默认勾图在左、文本紧跟（左对齐）。要居中在**节点上**设 `alignment = 1`（不是 theme 里，theme 无此项）。
3. **勾选框图要用"专用方形图"**：别用 CheckButton 的开关滑块图。CheckBox 用方形 checked/unchecked（见 [5.12] 对比），选中态可自生成"navy 方块 + 青勾"SVG（见 [5.13]）。
   - 提醒：CheckBox 的 icon **按原图尺寸**绘制，theme 里放不大。嫌小就把图**导出成更大尺寸**覆盖（保留 import、uid 不变）自动变大。

### 5.15 物品框（物品栏格子）→ 可点击 + 外发光交互

需求：物品框排进物品栏，**一行 N 个多行**排列，点击时有**动态反应（外发光）**。做法 = GridContainer 排布 + TextureButton 承接点击 + shader 画发光 + script 用 Tween 平滑过渡。

**结构**（科技套：4 列 × 2 行 = 8 格，见 `scenes/theme测试-科技.tscn` 的 `Inventory/Grid`）：
```
PanelContainer (物品栏底图, theme_type_variation=PanelInventory)
└ GridContainer (columns=4, h_separation/v_separation=24, size_flags=4 居中)
  └ Slot0..7 : TextureButton
       material      = ShaderMaterial(物品框发光.gdshader)   ; 每格独立一份
       texture_normal= 物品框图
       toggle_mode   = true                                  ; 脚本里也会设
       ignore_texture_size = true, stretch_mode = 5          ; 撑满 123×123 且保持比例
       script        = 物品框.gd
```

**发光 shader**（`scenes/物品框发光.gdshader`, uid `uid://c3vkv12mqeei2`）：canvas_item，采样图形外围 8 方向 alpha 取 max，只在"当前透明、周围不透明"处出光 → 向外扩散的轮廓光。参数：
- `selected` 0→1 控制发光强弱（脚本 tween 它）
- `glow_color`（默认青 `#6bdbff` 一带）、`glow_size`（默认 4.0，发光扩散像素）

**脚本**（`scenes/物品框.gd`, uid `uid://c32iykwj5juga`）：`extends TextureButton`，`_ready` 里开 `toggle_mode`、接 `toggled`；切换时 `create_tween().tween_method` 把 shader 的 `selected` 在 0↔1 之间 0.2s 平滑淡入/淡出。**每格必须挂各自独立的 ShaderMaterial**（否则所有格共享一个 selected，一起亮）。

**关键前提**：发光靠图形四周的**透明边距**显现。物品框 PNG 若图形贴满到边缘，光扩不出来看不见 → 留透明边，或调大 `glow_size`。

**复用到别的套**：同一 shader/script 通用，换 `texture_normal` 和材质数量即可。想要别的反馈（放大、描边、变色）改脚本 tween 的目标属性或 shader 即可。

### 5.16 卡片内嵌进度条：代码控制数值 + 定位到卡片内部区域

需求：信息卡片内部有横线分区，要在**横线下方区域**嵌一条进度条，数值**由代码控制**（非拖拽）。

**结构**（见 `scenes/theme测试-科技.tscn` 的 `CardRow/Card1/Bar1`）：进度条做成**卡片 TextureRect 的子节点**，用锚点定位到卡片内部某区域（不是放在卡片下方的 VBox 里）。
```
Card1 : TextureRect (卡片图, 230×341)
└ Bar1 : TextureProgressBar          ; 子节点 → 叠在卡片图上、绘制在其之上
     layout_mode = 1                 ; anchors 模式（非容器子节点用锚点自由定位）
     anchor_left/right = 0.5, anchor_top/bottom = 1.0   ; 锚到卡片底部中点
     offset_left/right = ∓84, offset_top/bottom = -58/-43  ; 框:宽168 高15，居中，底部往上约50px
     texture_under = 空槽（通用）, texture_progress = 填充N
     script = 信息卡片进度.gd
```
- **定位卡片内某区域**：先 Read 卡片 PNG 看清分区线的比例位置（本例横线约在 74% 高、底部面板 74%~92%），把进度条锚到该区间中部。锚到**底部**（anchor 1.0 + 负 offset）比锚顶部更稳，卡片高度变了也贴着底。数值按目测给，运行后让用户说"上移/下移多少"再微调 offset。

**代码控制数值**（`scenes/信息卡片进度.gd`, uid `uid://dw3bggpcf3tph`, `extends TextureProgressBar`）：
- `mouse_filter = MOUSE_FILTER_IGNORE` → 不吃鼠标，拖不动，纯展示。
- 正式用法：游戏里直接 `卡片/Bar.value = 数值`（0~100）。
- 带 `@export var demo`：开则 `_ready` 里 `create_tween().set_loops()` 循环缓动数值——**测试场景里能看到"代码在驱动"**；正式用关掉、改由自己代码写 value。

**⚠️ 大坑：TextureProgressBar 最小尺寸 = 贴图尺寸，无法直接调窄**。
- 现象：把 offset 框设得比贴图窄（如贴图 191、框设 168），控件**不肯缩到 191 以下**，于是左边固定、右边被撑到 191 → **右侧顶出卡片**。
- 解法：开 **`nine_patch_stretch = true`** + 设 `stretch_margin_left/right`（本例 6）。最小尺寸解锁 → offset 框尺寸真正生效，贴图按框拉伸（两端 margin 保留端点、中间拉伸），居中不顶边、两侧留白可控。
- 想让条比贴图**窄**（留边距）几乎必开 nine_patch；否则只能用原图宽。

### 5.17 面板内摆放子元素：图标 + 进度条（锚点定位）

需求：在一个固定尺寸 Panel（如单成就栏 716×174）里，**左侧放图标**（不顶边、留间距）+ **中间偏下放进度条**。

**通用套路**：Panel 是 Control，直接把子节点用**锚点+offset**摆进去（`layout_mode = 1`）。不要用容器（HBox/VBox）——面板内自由定位用锚点更直接可控。

**左侧图标**（垂直居中、距左边留间距，见 `AchBar/Icon`）：
```
Icon : TextureRect
  layout_mode = 1
  anchor_top = 0.5, anchor_bottom = 0.5     ; 锚到左侧中线 → 垂直居中
  offset_left = 34                          ; 距左边 34px（留间距，不顶边）
  offset_top = -60, offset_bottom = 60      ; 高 120，围绕中线对称 → 竖直居中
  offset_right = 154                        ; 宽 120（154-34）
  expand_mode = 1, stretch_mode = 5         ; 保持比例装进 120×120 框
```
- 图标本体 119×129，装进 120×120 框 + keep-aspect-centered，不变形。

**中间偏下进度条**（水平居中、竖直偏下，见 `AchBar/AchProg`）：
```
AchProg : TextureProgressBar
  layout_mode = 1
  anchor_left/right = 0.5, anchor_top/bottom = 0.5   ; 全锚到面板中心
  offset_left = -150, offset_right = 151             ; 宽 301，水平居中
  offset_top = 28, offset_bottom = 60                ; 高 32；正数=从中心往【下】偏 → “中间偏下”
  texture_under = 空槽, texture_progress = 填充
  texture_progress_offset = Vector2(14, 7)           ; 复用现成条形进度条的配法
  ; 数值代码控制：AchBar/AchProg.value = 数值
```
- **“偏下”原理**：垂直锚 0.5（=面板中线），`offset_top/bottom` 给正值就是整体往下推。本例 top=28 → 条中心落在约面板 70% 高处。想更下/更上就整体加/减这两个值（保持差=条高 32）。
- 直接**复用项目里已做好的进度条**（本例 `Prog`：301×32、空槽+填充、`texture_progress_offset (14,7)`、代码控数值），不用重配。

**微调经验**：位置一律目测先放，运行后按用户“再往下/往上一点”整体加减 `offset_top`+`offset_bottom`（同增同减，条尺寸不变），每次 ~8px 一档比较跟手。

### 5.18 文字 tab bar（单选 + 选中框移动 + 文字变色）

需求：一条 tab bar，**文字标签**，点击切换选中；**只高亮**、不切换内容面板。本质同[5.10]导航栏（单选+选中框移动），差别只是把「图标 Item」换成「Label Item」，并额外**改选中/未选文字色**。

**素材可直接复用导航栏的**：背景 = `横导航栏背景.png`(783×88)，选中框 = `横导航栏图标选中框.png`(169×81)。不必单独出图。

**结构**（见 `scenes/theme测试-科技.tscn` 的 `Tabbar`）：
```
Tabbar : TextureRect (背景, script=文字标签栏.gd)
├ Highlight : TextureRect (选中框 169×81, layout_mode=0)   ; 位置由脚本移动
├ Item0 : Label  ("全部")   layout_mode=0, offset 定位, 居中对齐, font_size 覆盖
├ Item1 : Label  ("装备")
├ Item2 : Label  ("道具")
```

- **标签均分**：4 个 tab 在 783 宽里，中心 = `783/8*(2i+1)` ≈ 98/294/489/685；每个 Label 宽 169（=选中框宽）、`horizontal/vertical_alignment=1` 居中；offset_left = 中心-84.5。**第一个 Item0 的 offset_left 别忘了设**（默认 0 会偏左、间距不均——踩过）。

**脚本**（`scenes/文字标签栏.gd`, uid `uid://bctf18wc3nfkl`, `extends TextureRect`）：
- 收集 `Item0/Item1/...`（Label），点击 → 选中框移到该 Label 中心、发 `selected(index)` 信号。
- **文字变色**：`select()` 里给选中项 `add_theme_color_override("font_color", color_on)`、其余 `color_off`。

### 5.19 Godot `Tree` 控件皮肤（原生控件，非皮肤图）

**区分**：项目里的 `tree.png`/`天赋树.png` 是**皮肤大图**（TextureRect 静态展示）；本条说的是 Godot **原生 `Tree` 控件**（可展开/折叠的层级列表），要在 `.tres` 里按 theme 格式配它的皮肤。二者无关，别混。

### 5.20 输入框文字：字号要显式设、多行左边距要够

**踩过的坑**：`LineEdit`/`TextEdit` 若不配 `font_sizes/font_size`，用的是 Godot **默认 16**，比其他控件（按钮 36）小一大截，显得很小。输入框的文字**必须显式设字号**。

**改法**（`第六套-科技.tres`）：
```
LineEdit/font_sizes/font_size = 40    ; 单行；输入内容比按钮标签(36)略大更清晰
TextEdit/font_sizes/font_size = 40    ; 多行；与单行一致
```
- 字号给 **40**（输入内容要清楚，比按钮 36 略大是常见做法）。

**多行文字顶左 → 加大左内边距**：`TextEdit` 用的 StyleBox（本例 `Text_normal`）默认 `content_margin_left` 偏小，文字贴左边框。加大到 **72**（`content_margin_left = 72.0`）留出间距。
- 注意：`content_margin` 是文字区内边距，和 StyleBoxTexture 的 `texture_margin`(9-patch 边框)是两回事。文字贴边就调 `content_margin_left`。
- 单行 `LineEdit`（本例 `Input_normal`）左右 `content_margin` 已是 80，间距够，不用动。

**通用**：任何输入类控件（LineEdit/TextEdit）配皮肤时，顺手把 `font_size` 和 `content_margin` 一起设好，别留默认。

### 5.21 导航栏选中反馈：白色发光（替代选中框）

需求：横/竖导航栏点击图标时，选中的图标**白色发光**，去掉原来的贴图选中框。本质是复用[5.15]物品框发光 shader，把颜色设白、由单选脚本驱动。

**结构**（见 `scenes/theme测试-科技.tscn` 的 `Navbar`/`VNavbar`）：导航图标是 `TextureRect`（`Item0/Item1/...`），各挂一个独立 `ShaderMaterial`。
```
[sub_resource type="ShaderMaterial" id="NavMat0"]   ; 横导航每图标一个 NavMat0..6
shader = ExtResource("67_glow")                     ; 复用 物品框发光.gdshader
shader_parameter/selected = 0.0
shader_parameter/glow_color = Color(1, 1, 1, 1)     ; ← 白色发光（物品框那套是青色）
shader_parameter/glow_size = 3.0                    ; 导航图标较小，3 比物品框的 4 精致
```
- 横导航 7 个 `NavMat0..6`、竖导航 6 个 `VNavMat0..5`，**每图标独立一份**（共用一个会一起亮）。
- 图标节点加 `material = SubResource("NavMatN")`。

**脚本**（`导航栏单选.gd`, uid `uid://bqg8cxu880ans`）：在 `select(index)` 里调 `_apply_glow(index)` —— 遍历所有 Item，选中的 `selected`→1、其余→0，`create_tween().tween_method` 平滑 0.2s。无 material 的 Item 自动跳过（`mat == null` continue），所以横竖共用这一个脚本、不影响别处复用。

**（备选）方案 A = 白色发光替代选中框**：*若*采用发光，就删掉 `Navbar`/`VNavbar` 下的 `Highlight` 选中框节点，选中反馈只靠发光。（脚本 `_move_highlight_to` 有 `_highlight == null` 判断，删了不报错。）想两者都要就保留 Highlight。**注意：当前项目并未采用此方案——Highlight 选中框保留在用、发光未启用。**

**坑/提醒**：

### 5.22 弹窗/面板关闭按钮（✕ 图标：点击隐藏 + 按压变暗）

需求：给弹窗、提示弹窗、物品栏、成就栏、信息卡片等的**右上角**加取消图标 ✕，点击让该容器消失，按压有变暗动效。

**脚本**（`scenes/关闭按钮.gd`, uid `uid://bnsjij4arqsad`, `extends TextureButton`）：
- `@export var target: NodePath`：要关闭的目标节点；**留空则默认关闭父节点**（`get_parent()`）。
- `button_down` → `modulate = Color(0.6,0.6,0.6,1)` 变暗；`button_up` → 恢复 `Color(1,1,1,1)`。**按压变暗只需一张图**，不用额外的 pressed 态贴图。
- `pressed` → 目标 `.hide()`。
- 通用，8 处共用这一个脚本。

**节点**：右上角 `TextureButton`，锚右上：
```
CloseBtn : TextureButton
  layout_mode = 1
  anchor_left = 1.0, anchor_right = 1.0        ; 锚到父的右边
  offset_left = -68, offset_right = -28        ; 宽40，距右边28
  offset_top = 28, offset_bottom = 68          ; 距顶28
  texture_normal = 取消图标.png (青色✕ 30×30)
  ignore_texture_size = true, stretch_mode = 5 ; 图标缩放到按钮框
  script = 关闭按钮.gd
```
- 大弹窗用 40×40/边距28；矮成就栏用 32×32/边距20；窄卡片用 30×30/边距32（各按容器大小调）。
- 微调"往里/往下"：加大边距即整体内移（左移=加大右边距，下移=加大上边距）。

**⚠️ 大坑：容器类节点（PanelContainer 等）里放浮层，✕ 会跑到中间/被缩进**：
- 现象：物品栏 `Inventory` 是 **PanelContainer**，把 CloseBtn 当内容子节点①强制拉伸铺满（锚点失效→图标居中）②按 `content_margin` 内缩。结果 ✕ 陷在物品框区里，不在面板角。
- 解法：**在容器外面套一层普通 `Control`（InvWrap）**，✕ 挂这层、锚 Control 右上角（=面板真右上角）；容器铺满这层。结构：
  ```
  InvWrap (Control, 750×334)
  ├ Inventory (PanelContainer, 铺满) → Grid → 物品框
  └ CloseBtn (✕, 锚 InvWrap 右上角，独立于物品框)
  ```
- 反之，普通 `Panel`/`Control`/`TextureRect`（弹窗、卡片）不管理子节点布局，✕ 直接作子节点锚右上即可，无需套层。
- **⚠️ Grid 居中坑（新建/套层都要注意）**：物品栏的 GridContainer **必须**设 `size_flags_horizontal = 4` + `size_flags_vertical = 4`（居中）。**新建时漏设、或套层时忘抄**，都会让 Grid 变默认 Fill → 被 PanelContainer 拉满宽 → 物品框被拉宽、整体靠左不居中。（科技和日系两套都在这栽过。）改完**打印 `grid.size` 核对**：等于自然宽（列数×框宽+间距，如 4×121+3×24=556）= 居中成功；比自然宽大 = 仍被拉宽偏位。

**验证**：`--script` 跑 SceneTree，打印 `close.global_position` 和面板角坐标算差值确认贴角；`img.save_png` 截图核对。

### 5.23 浅色风格：文字要显式配深色（默认是白字，看不见）

Godot 控件文字**默认接近白色**，深色风格正好，但**浅色风格**（浅色按钮/输入框/面板）下白字在浅底上几乎看不见 → **必须显式把文字配成深色**。第七套「未完成」风即浅色风格，全套配了深字。

**要配深色 font_color 的控件**（浅底上有文字的）：
```
Button/colors/font_color = Color(0.15, 0.13, 0.1, 1)        ; 近黑
Button/colors/font_hover_color / font_pressed_color / font_focus_color = 同上
Button/colors/font_disabled_color = Color(0.45, 0.45, 0.45, 1)  ; 灰
; Button2/Button3/ButtonOk/ButtonFail/MenuButton/OptionButton/CheckBox/CheckButton 各自同样配
LineEdit/colors/font_color = Color(0.12, 0.12, 0.15, 1)     ; 输入内容黑
LineEdit/colors/font_placeholder_color = Color(0.45,0.45,0.5,0.7)  ; 占位符灰
LineEdit/colors/caret_color = 深色                          ; 光标（否则白光标看不见）
; TextEdit 同 LineEdit
Tree/colors/font_color / font_hovered_color / font_hovered_dimmed_color = 深色
```

**坑/要点**：
- **变体不继承基类颜色**：`ButtonPink`/`Button2` 等 `theme_type_variation` **不会**自动用基类 `Button` 的 font_color，**每个变体都要单独配**。
- **按钮多状态**：只配 `font_color`（normal）不够，`font_hover_color`/`font_pressed_color`/`font_focus_color` 都要配，否则 hover/按下瞬间字变回默认白。
- **Tree 悬停**：`Tree/colors/font_color` 只管正常态，**悬停要另配 `font_hovered_color` + `font_hovered_dimmed_color`**，否则鼠标划过时字变浅。
- **caret_color 别忘**：输入框光标默认浅色，浅底上看不见 → 配深色。
- **例外——深底上的文字要浅色**：如果某文字显示在**深色场景背景**上（如测试场景的分组标题 Label、导航栏文字），那它要配**浅色**，不是深色。判断依据是「文字落在什么底色上」，不是「整套什么风格」。第七套即：按钮/输入/Tree 在浅色控件上→深字；标题 Label 在深色背景上→浅字（`Color(0.9,0.9,0.93,1)`）。

### 5.24 纯色风格 + 换色模板（第二套「纯色黄」为样板，`零 PNG`）

纯色风格 = **全部 StyleBoxFlat 代码绘制，不用任何贴图 PNG**。第二套即样板，可当「换色模板」：给一个主色就能推导整套同结构的新配色（如「纯色蓝」「纯色绿」）。

**换色只改 7 个颜色（tres 顶部有注释块列出）**，全套跟着变：
```
主色 normal   = #F2C230   ; 按钮/进度条填充/边框高亮/Tree强调
主色 hover    = #FFD84D   ; 比 normal 亮一档
主色 pressed  = #C7991F   ; 比 normal 暗一档
主色 border   = #8A6A15   ; 主色描边(最暗)
on-accent 文字 = #2E2405   ; 压在亮主色上的深字(按钮文字)
面板底色      = #1E1E22   ; 深炭底(弹窗/物品栏/Tree面板)，配不同 alpha
浅色文字      = #EDE9DF   ; 深底面板上的浅字(Label/输入/Tree)
```
推导规律：主色三态就是「基准色 + 提亮 / + 压暗」；深底面板固定深炭色系不随主色变（换色时通常只改主色系 5 个 + 保留深底），若要连底色都染主色调，把面板 bg 混入少量主色即可。

**图片类组件 → 纯色几何替代**（纯色风格无 PNG，用形状/符号代）：
- **导航栏**：不用图标图，用一排 `toggle_mode=true` + 同一 `ButtonGroup` 的 Button（内置单选，选中态即 pressed 样式，**零脚本**）。比 `导航栏单选.gd` 更省。
- **虚拟摇杆 / 滑块拖动键 / 物品框**：用 `Panel` + 变体（`PanelGrabber` 圆钮、`PanelSlot` 方格）代替 TextureRect/TextureButton。圆形靠 `corner_radius` 拉满。
- **关闭 ✕**：用 `Button` + `ButtonClose` 变体（圆底），`text="✕"`，**不用 `关闭按钮.gd`**（那个 extends TextureButton）。hover 变红即视觉反馈。
- **勾选指示（CheckBox 勾号 / CheckButton 开关滑块 / Tree 箭头）**：这些**必须有图标**才显示，StyleBoxFlat 画不出 → 用**矢量 SVG**（`UI/纯色黄/*.svg`，非位图、可跟随主色重生成）。换色时同步改 SVG 里的 `fill`/`stroke` 十六进制。
- **信息卡片图标 / 成就图标 / 成功失败标记**：用 `PanelSlot` 小方块 + 里面放符号 Label（`✓`/`✕`/`🏆`）。

**滑块填充用脚本控的 `Fill` 子节点**（見 5.8）：纯色滑块的 `Fill` 用 `ColorRect`（`custom_minimum_size` 交叉轴给填充厚度），`Track` 用 `PanelSlot`，`Grabber` 用 `PanelGrabber`。脚本 `贴图滑块.gd`/`贴图滑块竖.gd` 的 `_grabber`/`_knob` 类型已放宽为 `Control`，Panel/TextureRect 都能挂。

**坑**：
- **Grabber/Knob 用 `Panel` 会吃到默认 `Panel` 主题样式**（那是弹窗大框 Pop_bg）→ 必须给它们套 `PanelGrabber` 变体，否则渲染成一个大黑框。
- **复用脚本的节点类型**：`虚拟摇杆.gd`/`贴图滑块*.gd` 原本 `@export`/`var` 声明为 `TextureRect`，纯色用 `Panel` 会类型不符。已把 `_knob`/`_grabber` 声明放宽为 `Control`（只用到 position/size/mouse_filter，都是 Control 成员），向下兼容其余九套。

### 5.25 纯矢量自绘一整套（皇室战争第十一套，`零 PNG`，脚本可复现）

前十套都靠现成 PNG 素材。**这套没有对应素材库**，整套 80 张图由 `tools/生成皇室战争素材.py` 生成 SVG。适用于「有明确风格参照、但手上没图」的情况。

**为什么走 SVG 不走 StyleBoxFlat**：皇室战争的按钮 = 竖向渐变体 + 极厚深色描边 + 底部深色唇边（3D 厚度）+ 顶部白色高光带。StyleBoxFlat 只有单色 `bg_color`，画不出渐变和唇边；SVG 的 `linearGradient` 可以，且导入后就是普通 `Texture2D`，theme 结构和 PNG 套**完全一致**（StyleBoxTexture + `texture_margin`），无需特殊处理。

**已验证**：Godot 4 的 SVG 导入器正常光栅化 `linearGradient`（探针实测按钮竖向从 `#68ccfb` 渐变到 `#1d7dd6`）。

| 金（强调/购买） | `#FFE479` → `#F0A81E` | `#5E3306` | `#C07C0E` |
| 绿（确认） | `#B4EE68` → `#3CA22B` | `#123C0A` | `#2A7A1C` |

| 紫（圣水条） | `#F07AF0` → `#9C1EC4` | — | — |

**白字粗描边**是这风格的标志性文字处理：`font_color = 白`、`font_outline_color = 深底色`、`constants/outline_size = 8`（Label 用 7、小字用 6）。每个变体的描边色跟随自己的按钮色系（金按钮用棕描边而非蓝）。

**按下态用独立贴图，不是 modulate**：本套 normal/pressed 两张图的**底唇高度不同**（pressed 图里本体下沉、唇边收窄），才有"按下去"的物理感。配套把 pressed StyleBox 的 `content_margin_top/bottom` 互换（12/22 → 22/12），文字跟着一起沉。hover 仍用 normal 图 + `modulate 1.14` 提亮即可。

**踩到的坑**：
- ❌ **面板顶部高光带高度别按控件高比例给**（曾写 `min(ht/4, 90)`）。9-patch 只保护 `texture_margin`（60）以内的区域，90px 的高光带伸进了可拉伸的中段，纵向拉伸时被拉长。→ 固定 36px，整条落在 margin 保护区内。
- ❌ **内凹层 `opacity=0.55` 看不见**：和面板底色太近，深底上等于没画。→ 直接给实色 `#08234A` + 一条 `opacity 0.35` 的顶部内阴影。
- ❌ **`MenuButton` 默认 `flat = true`**，不画 StyleBox，只剩文字。→ 场景里显式 `flat = false`（其他按钮类无此默认）。
- ❌ **`CheckBox/colors/font_pressed_color` 给强调色**会让**已勾选项**的文字长期变色（`button_pressed` 状态下 pressed 色一直生效），和未勾选项不一致。→ 保持白字。
- ⚠️ **图标画在 56×56 框里要撑满**：奖杯初版只占 `y=11..45` 显得细小，加双耳+粗底座撑到 `8..50` 才够份量。环形加载的底环用近黑 `#0A2340@0.6` 在深底场景上**看不见** → 改浅蓝 `#7ED3FF@0.30`。
- ⚠️ **长标题 Label 撑爆视口宽**：Label 默认不换行，19 行超长分组标题把 VBox 最小宽撑到 **994** > 竖屏 804，右侧内容全被裁。→ 全部加 `autowrap_mode = 2`。改完再用探针查 `Inner.get_combined_minimum_size().x` 是否 ≤ 可用宽（视口 − Margin 左右）。
- ⚠️ **卡片内嵌进度条别拿大图缩**：信息卡片仅 240 宽，塞 320 宽的条得开 `nine_patch_stretch`，22px 高的填充会被纵向拉胖（同 5.16）。→ 另生成一对原生窄尺寸图（`卡片进度条空槽` 180×24 / `填充` 164×14），零拉伸。

**截图验收的两个陷阱**（比 5.6 更细）：
1. **`--headless` 拿不到图**：渲染器是 dummy，`viewport.get_texture()` 报 `Parameter "t" is null`。必须去掉 `--headless` 并加 `--rendering-driver opengl3`。
2. **`SubViewport` 这条路取不到内容**（把场景塞进超大 SubViewport 整页取图，得到的是纯背景色，采样 94% 是底色）。→ 改用 **root Window 视口 + 逐屏滚动 `ScrollContainer.scroll_vertical` 截图**，一屏一张。存图后**顺手统计非背景像素占比**，避免"存了张空图却以为通过"。
3. 真渲染进程退出**可能触发 .tres/.tscn resave 污染**（见 [[godot-editor-open-tscn-churn]]）→ 跑前 `md5 -q` 记基线，跑后 diff 核对。本套全程零污染。

**复现/换配色**：改 `tools/生成皇室战争素材.py` 里的色 token → `python3 tools/生成皇室战争素材.py` → `Godot --headless --path . --import`。文件名不变故 uid 不变，theme 和场景引用**无需改动**（符合 4.2）。

**这次踩的坑**：

- ❌❌ **结构线定太暗，画了但人眼看不见 —— 而"提亮色值"只修了一半。** 第一版 `LINE #0A6E70 @0.55` 只有 1.73:1、`LINE2 #0E3A3C @0.10` 只有 1.03:1（纯黑底上），截图层内容占比 2.71%–3.80% 当场卡在 4.0% 下限。**这不是"线框风格天生稀疏"可以解释的**：量对比度分布发现 76%–95% 的非背景像素低于 1.5:1。第一次修只换了色值（`#1FA8AA` / `#12666A`），占比仍不达标 —— 因为**透明度没跟着提**，斜纹 `@0.10` 换了亮色仍是 1.1:1。**色值和透明度是乘在一起的，只改一个等于没改。** 最终两处一起定：结构线 `LINE @0.85 = 5.4:1`、斜纹 `LINE2 @0.45`、填充斜纹 `CYAN @0.62 = 5.3:1`，占比回到 4.09%–6.90%。
- ❌ **"低对比像素占多数"不能直接当缺陷判据 —— 先拿已交付套跑同一把尺子。** 修完后我的分析器仍报 77%–95% 低于 1.5:1，看着像没修好。拿**用户已验收的战术锋线**跑同一脚本：56%–82%，同一区间 —— 说明这个数大半是辉光和抗锯齿的过渡像素，**任何带发光的套都这样**。
- ❌ **更关键：那 95% 是我自己的口径造出来的假象。** 我的分析器把「非纯黑」全算内容，于是面板极暗底 `PANEL #050A0C`（渲染出来 `rgb(5,10,12)`，1.06:1）被算成"看不见的内容"；而验收脚本的 `背景判定器` 按「够暗且够中性」本就把它判成**背景**。改用**验收脚本自己的判定器**重量，线框仪表 22.9%–57.5% 达 3:1，反而优于战术锋线的 14.7%–53.1%。**教训：拿自己另写的一把尺子去质疑闸门的结论前，先确认两把尺子的背景口径一致** —— 否则会照着一个不存在的故障去改素材。
- ⚠️ **斜纹网格必须裁在内容区**：斜纹是一组等距 45° 直线，若按整图铺满，九图拉伸时中段斜率变了、间距不再等距。`hatch()` 手算直线与矩形的交点（不用 `clipPath`，Godot SVG 导入器对它支持不可靠）。
- ⚠️ **括号臂长一律固定**（长 20 / 短 12），不随尺寸走比例 —— 否则宽按钮上臂会伸出 `texture_margin` 保护区。本套的括号角**天然适合九图**：角落细节固定、中段本来就是空的，拉伸只拉到空白区。
- ⚠️ 场景栏 / 单成就栏的 `texture_margin_top` 只有 32 / 40，**不画顶部刻度尺**（`spine=False`）—— 与 5.28 同一个坑：固定高度的顶部装饰要逐图确认落在哪张图的保护区内。

**验收（四层全过，`bash tools/验收/全量验收.sh 线框仪表` 退出码 0）**：
1. 素材层：81 张 SVG 合法、零位图、文件名与契约 81/81 对账、尺寸逐张对账通过；`cp -R` 后重跑 `diff -r` 为空（字节级复现，本套零伪随机）；
2. 静态层：`texture_margin` 全部在界内、`ext_resource` 顺序正确、uid 合法唯一且交叉引用对账、素材全部着落、HBox 纵向拉伸通过；轨道／分隔线短轴 `content_margin` 判据（`检查主题.py [8]`）从派生源继承，直接通过；
3. 几何层：42 个贴图控件尺寸对账通过、`Inner` 最小宽 750 ≤ 视口 804；

### 5.30 第七套纯矢量自绘（深海泡泡第十七套，`零 PNG`，深海水下／半透明水膜）

风格 = 深蓝黑底 + 半透明水膜面 + 径向渐变气泡 + 近白高光新月。**主体是有填充的半透明面，几乎不画硬边框** —— 这是和 5.29 线框仪表的根本对立面。

素材 `UI/深海泡泡/`，生成脚本 `tools/生成深海泡泡素材.py`，主题 `theme/第十七套-深海泡泡.tres`。

**与线框仪表的区分度（开工前就点明的风险，两套都会用到圆／弧）**

硬约束禁止「换了配色的同一套」，所以区分度全部押在**表面处理**上，不靠调色盘也不靠「都是圆」。交付时实测（数元素、数渐变、算平均 `stroke-width`，可复现）：

| 指标 | 深海泡泡 | 线框仪表 | 战术锋线 |
|---|---|---|---|
| 有填充元素数 | **266** | 70 | 144 |
| linearGradient | 63 | 0 | 59 |
| **radialGradient** | **157** | **0** | **0** |
| 平均 stroke-width | 1.51 | 0.76 | 3.11 |

`radialGradient` 157 vs 0 是最硬的一条：线框仪表零实填（`fill="none"` 的发丝线），本套每颗气泡一个径向渐变。**配色接近时务必留下这类实测记录**，否则半年后没人分得清两套是不是同一套换色。

**七类骨架**（与前六套全不同）：

| 类 | 本套骨架 |
|---|---|
| 面板 | 大圆角水膜穹顶（**连续柔边**，不是断开括号）+ 顶部高光新月 + 角落保护区内的气泡簇 |
| 按钮 | 双层水滴丸（外层水膜 + 内层亮膜 + 顶部新月 + 右端上浮气泡）；按下＝内层下沉 3、新月收到 32%、气泡收为一颗、底缘加沉影线 |
| 进度 | 液面分层玻璃管（水平水层渐变 + 前端亮液面线），**不是斜纹也不是实色棱条** |

| 滑块 | 双层水膜细管（上亮膜/下暗膜 + 中央亮液线，**全程无刻度**）+ 双环气泡键 |
| 物品框 | 圆角水膜框 + 左上气泡簇 + 右下弧形液面刻度（走 `TextureRect`，几何自由） |
| 导航 | 选中格整颗胶囊水泡（半透明填充 + 高光新月），轨是两道渐隐水平水线 |

摇杆为同心水膜圆盘 + 8 颗等距气泡环（线框仪表是同心空心环 + 24 道刻度须）。**气泡是本套的贯穿单元**，取代线框仪表的圆环／弧段。

**本套新增的一条硬约束：圆角半径必须 ≤ 最小 `texture_margin`**

这是前六套都没有的（它们是切角／括号／楔形，没有圆角）。静态层 `检查主题.py [2]` 只查「T+B < 图高、L+R < 图宽」（九图退化），**查不出这一条** —— 圆角 30 配边距 26 完全合法，但圆角有 4px 落在会被拉伸的中段，横向拉宽时那 4px 被抹平，圆角变成带直角小台阶的怪形状。派生只做机械替换、几何值不跟着变，所以**派生完必须自己量一遍**（本套实测到 20 处）。

修法是在生成脚本里建一张 `_九图边距` 表（数字逐个从派生出的 theme 量，不抄源套注释）+ `rx_of(name, want, short)` 钳制函数：按钮 26、输入框 24/26、面板 44~58、进度填充 **7**、滑块填充 **4**。最终 43 张会被拉伸的九图全部落进保护区。填充图边距最小是对的 —— 它要从 0 宽拉到满宽，圆角越大越容易在窄值处露台阶。

**拉伸安全按「这张图会不会被拉伸」分两类画**：

- 走 `TextureRect`（尺寸严格等于控件，不拉伸）：物品框/卡牌框/占位符、摇杆两张、全部图标、checkbox、tree 箭头、环形加载、步进、分界线 —— 气泡和弧任意画。
- 走 `StyleBoxTexture`／九图（会拉伸）：气泡**只许落在角落保护区内**（`CORNER=22`，小于最小的面板/按钮/输入框边距），中段一律只用「与拉伸轴平行的直线」和「沿拉伸轴不变的渐变」。
- 进度/滚动/滑块的边距只有 4~17，**保护区放不下气泡**，所以这三类中段一颗气泡都不画，改用水平水层 + 液面线（横向拉伸时逐行不变）；竖版把水层转成竖列，拉伸轴换了安全条件跟着换。

高光新月是例外，**允许跨中段** —— 横向拉伸时它跟着变长，而水面高光本就随宽度延展，这是想要的。

**水膜不透明度有下限（承 5.29 那条教训的另一面）**

截图层的 `背景判定器` 对本套底色 `rgb(6,19,31)` 走「三通道各自 ±23」分支（`max=31 > 暗底上限 30`），容差带是 r0-29 / g0-42 / b8-54。**动笔前先按闸门自己的口径算过**（合成到底色再按 WCAG）：

```
FILM @0.10 -> 1.23:1 整片落在容差带里，会被判成背景★
FILM @0.18 -> 1.52:1   @0.24 -> 1.82:1   @0.28 -> 2.05:1
LINE @0.55 -> 2.91:1（不够）   @0.85 -> 5.23:1   满 -> 6.86:1
```

所以定死：**水膜填充 ≥0.18、结构线一律 ≥0.85**。这是 5.29「色值和透明度是乘在一起的，只改一个等于没改」的正向应用 —— 那次是画完才发现看不见，这次是动笔前先算。

**这次踩的坑**：

- ⚠️ **端头一律 `round`**，与 5.28 战术锋线的 `butt` 正好相反：本套要柔和。线宽也比线框仪表加粗一档（2.2/1.6/1.0 对 1.5/1.0/0.6）。
- ⚠️ **水膜渐变用 `stop-opacity` 变化，不用两个色值**：语义是「同一种水，厚度不同」，换成两个色值会出现色相漂移，在半透明叠加下很脏。
- ⚠️ **新月用二次贝塞尔而不是 `arc`**：新月很扁，用圆弧要给一个巨大的 `r`，Godot 导入器在 `r` 远大于弦长时会算出可见锯齿。
- ⚠️ **占位文字和节标签会带着前几套的语境一路继承**：本套派生源里还写着「义体区1/2/3」（从义体裂界经线框仪表传下来）、以及「霓虹红」「金框」「金色箭头」等与画面不符的配色词。逐条按**实际渲染出来的颜色**改（先核生成脚本里的 `accent`/`pal`，别把标签改成另一个错的）。
- ⚠️ **对比度分布这把尺子在半透明风格下读数天然偏高**：本套合计 ≥3:1 占 16.8%、<1.5:1 占 41.5%，看着像 5.29 那次「画了但看不见」。但那次是 76%–95% 低于 1.5:1 且占比卡在 4% 下限；本套占比 21%–42%。拿已交付的战术锋线跑同一把尺子：<1.5:1 合计 **67.0%**，比本套还高 —— 大面积半透明填充叠在深底上必然产生大量 1.5–3:1 的像素，**这是风格决定的，不是缺陷**。（承 5.29：拿另一把尺子质疑闸门结论前，先用已交付套校准。）
